# 탐침 정본 (probes) — 요구사항·스펙의 표준 누락 패턴

> 이 목록은 두 층이 공유하는 정본이다. **spec-driller 스킬**은 요구사항 레벨에서 같은 탐침을 **사람에게 묻고**(`skills/spec-driller/SKILL.md`), **spec-writer**는 스펙 레벨에서 검증 항목을 옮길 때 **스스로 자문한다**(`agents/spec-writer.md`). 이중 방어다 — 실전에서 함정이 추가되면 두 층이 같이 강해진다. 다른 문서의 목록과 갈리면 이 파일이 정본이다.

## 탐침 목록

| # | 탐침 | 묻는 것 | 예 | spec-writer 자문 |
|---|---|---|---|---|
| P1 | 모순 | 조항끼리 충돌하는가. 같은 말이 다른 뜻으로 쓰였는가 | "삭제하면 기록도 지운다" vs "기록은 불변이다" | 자문 아님 — 발견 즉시 계획 결함 보고 |
| P2 | 실패 경로 | 각 동작이 실패하면 무엇이 보여야 하는가. 부분 성공은 가능한가 | 저장 실패, 외부 API 타임아웃, 트랜잭션 중단 — 실험 4차의 실측 누락 유형 | **의무** |
| P3 | 경계 | 범위의 양 끝, 빈 것과 없는 것, `null`과 `0` | 목표치 0인 할 일, 빈 목록, 최대 길이 | **의무** |
| P4 | 동시성·순서 | 같은 일이 두 번 일어나면, 순서가 뒤바뀌면 | 중복 제출, lost-update(잃어버린 갱신) — PLAT-581 reviewer의 실측 검출 유형 | **의무** — 테스트로 표현 불가면 체크리스트로 |
| P5 | 암묵 가정 | 문서가 말하지 않고 전제하는 것은 | 타임존(이 계열 저장소의 대표 함정), 권한, 단일 사용자 가정 | 권장 |
| P6 | 상태 전이 | 어떤 상태에서 이 동작이 금지되는가. 되돌리기는 | 완료된 항목의 수정, 삭제 후 복원 | 권장 |
| P7 | 규모·성능 | 10배가 되어도 같은 답인가 | 목록이 1만 건일 때의 페이지네이션 | 권장 |

"spec-writer 자문" 열은 검증 항목 하나를 스펙으로 옮길 때마다 의무적으로 자문하는 탐침(P2·P3·P4)과, 전체를 한 번 훑을 때 보는 권장 탐침의 구분이다.

## 갱신 기준 — 어떤 함정이 탐침이 될 자격이 있는가

PR 시점 함정 이관(`rules/core.md` 커밋·PR 절)의 영구 자리 중 하나가 이 파일이다. 등재 기준:

1. **모든 층(드릴링·스펙·G1·G2·G3)을 통과해 놓친 결함**의 원인이 된 질문이면 — **1회 발생으로도 자격이 있다.** 어느 층도 묻지 않은 질문이라는 증거이기 때문이다
2. 그 외에는 **서로 다른 작업에서 2회 이상 반복** 관측됐을 때
3. **일반화해서 적는다** — 특정 저장소의 함정("X 모듈의 Y 플래그")이 아니라 임의의 요구사항에 던질 수 있는 질문으로 바꿔 적는다. 저장소 고유 함정은 그 저장소의 참조 문서에 남긴다
