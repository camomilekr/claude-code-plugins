# 참조 — Jira 티켓 조회 상세

티켓 본문이 비어 보이거나, 첨부 이미지를 해석해야 하거나, 조회가 실패했을 때 읽는다. 기본 조회 절차는 `rules/jira.md`에 있다.

## `customfield_10101` 보충 조회 (본문이 비어 보이면 필수)

WhaTap Jira 프로젝트에서 **부모 카드가 `개선` 이슈 타입인 경우** 본문이 `description`이 아닌 **`customfield_10101`(상세 설명)**에 저장된다. `description`이 비어 있으면 반드시 다음을 추가 조회한다:

```
mcp__claude_ai_Atlassian_Rovo__getJiraIssue(
  cloudId="whatap-labs.atlassian.net",
  issueIdOrKey="{KEY}",
  fields=["customfield_10101"],
  responseContentFormat="adf"    # markdown 옵션은 description만 변환한다
)
```

응답의 ADF JSON을 직접 읽고 한국어 마크다운으로 정리해 본문으로 쓴다 — `heading` → `## 제목`, `paragraph` → 단락, `bulletList`/`listItem` → `- ` 목록, `media` → 첨부 참조(`alt` 값), marks → `**bold**`·`` `code` `` 등. `customfield_10101`도 비어 있으면 **그제서야 진짜 "본문 없음"으로 간주**한다.

> **왜 강제하는가**: 본문이 비었다고 단정하면 카드에 명시된 해결 방향을 놓치고 잘못된 계획을 만든다. 실제로 본문이 `customfield_10101`에 있었는데 빈 본문으로 보고돼 사용자가 두 번 잡아준 사고가 있었다.

## 카드를 읽는 신호 우선순위

카드는 다음 우선순위로 해석한다. 아래로 갈수록 추측 의존도가 높아진다.

1. **카드 제목** — 가장 강한 신호. **본문·이미지가 제목과 충돌하면 제목을 우선시한다**
2. 본문의 **"기대 동작 / 실제 동작"**
3. 본문의 **"재현 경로"** — 영향 범위(파일·컴포넌트)를 추정하는 핵심 단서
4. 본문의 **"추정 원인"** — 작성자의 짐작이다. 코드로 확인하기 전에는 사실로 다루지 않는다
5. **이미지 + 본문 캡션**
6. **캡션 없는 이미지** — 추측 의존도가 가장 높다. 본문이 비고 이미지만 있으면 이미지 기반 추론임을 요약에 명시한다

카드에 **"작업 범위 한정"** 항목이 있으면 그것이 범위의 1차 근거다 — 이미지에 보이는 다른 양상을 범위로 확장 해석하는 것을 그 항목이 직접 막는다.

## 첨부 이미지 해석

**공식 MCP는 첨부 이미지를 내려받지 못한다.** 가끔 실패하는 것이 아니라 상수다 — 첨부 바이너리 다운로드 도구가 아예 없고(`fetch`는 이슈·페이지 ARI 전용), `attachment` 필드는 파일명·크기·`content` URL만 준다. 그 URL은 익명 접근이 `403`이고 MCP는 토큰을 클라이언트에 노출하지 않아 인증을 붙일 방법이 없다. **될 때까지 재시도하지 마라.**

이미지 판독이 필요하면 이 순서로 한다:

1. **Jira 조회 스킬로 조회한다** (`rules/jira.md`의 조회 우선순위). 스킬이 첨부를 로컬에 내려받고 경로를 알려 준다 — 그 경로를 `Read`로 열어 판독한다
2. 스킬을 쓸 수 없으면 **사용자에게 해당 이미지를 대화에 첨부해 달라고 요청한다**
3. 어느 쪽도 안 되면 **추측으로 메우지 말고** 이미지를 보지 못했음을 요약에 명시한다

**해석 우선순위 (필수)**:

1. **카드 제목·본문이 1차 신호다.** 이미지는 보조 자료다
2. 다수 이미지의 역할을 **가설로 분리**해서 분류한다 — 모든 이미지가 "문제 상황"이라고 단정하지 마라. 예: "정상 참고용 / 문제 상황", "Before / After"
3. **카드 제목·본문이 다루지 않은 양상**이 이미지에서 보이면 **별도 의문점으로 분리**해 검토 게이트에서 명시적으로 확인한다. 절대 그것까지 작업 범위로 자동 확장하지 마라
4. 카드 본문이 비고 이미지만 있을 때는 이미지 기반 추론임을 요약에 명시한다

> **왜**: 이미지에서 보이는 모든 어색함을 자동으로 작업 범위에 넣으면 사용자가 의도하지 않은 작업까지 늘어난 잘못된 계획이 된다. 실제로 카드 제목은 "데이터 없는 경우"였는데 이미지의 "툴팁 범례 가림"까지 확장 해석한 사고가 있었다.

## 실패·예외 처리

| 상황 | 대응 |
|---|---|
| 조회 실패 (401/403/404) | 응답 요지 + 원인 추정(브랜치명 오타로 잘못된 키 가능성 포함) + 권한·키 확인 요청 |
| 조회 스킬 실패 (비정상 종료·자격증명 없음) | **재시도하지 말고** 즉시 MCP로 1회 폴백. 첨부 이미지는 위 순서 2번(사용자에게 요청)으로 넘어간다 |
| MCP 미연결 | 연결 안내 후, 사용자가 원하면 티켓 없이 진행 (상태 전환은 전부 스킵) |
| 본문·이미지 모두 모호 | 강제로 계획을 만들지 말고 사용자에게 확인을 요청한다 |
